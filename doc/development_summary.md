# Network Monitor v2 开发总结

## 1. 项目架构

### 1.1 整体架构
- 采用前后端分离的架构设计
- 后端：Flask + Flask-SocketIO
- 前端：HTML5 + Bootstrap + Chart.js
- 实时通信：WebSocket (Socket.IO)
- 容器化：Docker

### 1.2 目录结构
```
network-monitor_v2/
├── app/
│   └── app.py          # 后端主程序
├── static/
│   ├── css/
│   │   └── style.css   # 自定义样式
│   └── js/
│       └── main.js     # 前端逻辑
├── templates/
│   └── index.html      # 前端页面
├── doc/                # 项目文档
├── Dockerfile          # Docker配置
├── requirements.txt    # Python依赖
└── README.md          # 项目说明
```

## 2. 技术栈详解

### 2.1 后端技术
1. **Flask框架**
   - 轻量级Web框架
   - 易于扩展
   - 适合快速开发

2. **Flask-SocketIO**
   - 提供WebSocket支持
   - 实现实时数据传输
   - 支持多种传输协议

3. **网络监控工具**
   - ping：网络延迟测试
   - iperf3：带宽测试
   - psutil：系统资源监控

### 2.2 前端技术
1. **Bootstrap 5**
   - 响应式布局
   - 现代化UI组件
   - 跨浏览器兼容性

2. **Chart.js**
   - 实时数据可视化
   - 流畅的动画效果
   - 支持多种图表类型

3. **Socket.IO客户端**
   - 实时数据接收
   - 自动重连机制
   - 跨浏览器支持

### 2.3 容器化技术
- Docker容器化部署
- 基于python:3.9-slim基础镜像
- 包含必要的系统工具（iperf3, ping）

## 3. 开发过程中的主要问题及解决方案

### 3.1 环境相关问题
1. **WSL2环境下的网络访问问题**
   - 问题：WSL2环境下网络接口访问受限
   - 解决：使用 `--network host` 模式运行Docker容器

2. **Docker容器中的系统工具**
   - 问题：容器中缺少必要的网络工具
   - 解决：在Dockerfile中安装iperf3和ping工具

### 3.2 网络监控相关问题
1. **网络延迟测量**
   - 问题：ping3库在容器环境中不稳定
   - 解决：使用系统ping命令替代，通过subprocess调用

2. **吞吐量计算**
   - 问题：psutil计算的吞吐量不准确
   - 解决：使用专业的iperf3工具进行带宽测试

3. **WiFi信号质量监控**
   - 问题：容器中无法访问主机无线网卡信息
   - 解决：添加条件判断，在不支持时返回0

### 3.3 实时数据传输问题
1. **WebSocket连接**
   - 问题：跨域访问限制
   - 解决：配置 cors_allowed_origins="*"

2. **数据更新频率**
   - 问题：过频繁的更新可能导致性能问题
   - 解决：设置1秒的更新间隔
